## Implementation

- [x] Added `TaskRemoteTakeover` and the `TaskHandoverGraphQLTransporting` protocol. The URLSession transport validates HTTP(S), sends manager bearer and manager-session headers, and decodes GraphQL responses. The in-process transport supports `GraphQLDocumentExecuting` chains.
- [x] Remote takeover fetches and recomputes the packet digest, rejects unpublished/checkpoint-failed repositories and non-URL remotes, resolves the local host id through `HostCapabilityResolver` with hostname fallback, reserves through GraphQL, materializes a published repository branch, creates the controller-issued local session id, imports the packet history bundle, runs from the resume step with `handover` and `rielaTask` variables, heartbeats, checks the fence before checkpoint/publish, enforces the 4 MiB report bound, and reports terminal session/deliverable state. `--clone-into` requires a repository deliverable.
- [x] An unauthorized/error or fenced heartbeat cancels the workflow, writes local `failed(.leaseLost)`, and skips report. The heartbeat task is awaited and stopped on successful report and all error paths. Auth token values are not rendered.
- [x] Added `task serve --takeover` with local or endpoint polling, trait filtering, oldest eligible task selection, unanswered-question skipping, one-at-a-time takeover, poll interval, `--once`, and clean cancellation. `task serve` without `--takeover` returns the P3 usage error.
- [x] Added takeover endpoint/auth/manager-session options, optional `--handover-id`, and the `--endpoint` plus `--force-orphan` usage rejection before local store lookup. Added no-target parsing and routing for `task serve`.
- [x] Changed shared routing paths: `Sources/RielaCLI/RielaCommand.swift` (serve kind and task-wide parsing), `Sources/RielaCLI/TaskCommands.swift` (serve dispatch), and `Sources/RielaCLI/TaskHandoverCommands.swift` (remote routing and flags). No other wh-18 shared paths changed.

It asserts A's task `succeeded`, a successor attempt with a `.takeover` entry from the predecessor, an `accept` decision for that attempt, an unfenced heartbeat response with non-null `expiresAt` and no errors, and `controllerTaskState == "succeeded"` in the command output. Companion: `testRemoteTakeoverOverProviderRefusesHostWithoutRequiredTraits` (traits `[]` fails with `host-traits-unavailable`, A's attempt list unchanged). ## Test-integrity repair changes

- `Sources/RielaCLI/TaskServeTakeover.swift`: added the `localDispatch` DI seam (production default `TaskDispatch(signalState:)`), and fixed a real serve bug: local mode dispatched the candidate without recording a takeover request, so `TaskDispatch` answered `waiting` (waitReason `handover`) and never reserved a successor. Serve now calls `TaskHandoverRuntime.requestTakeover` (idempotent while a takeover reservation is pending), as `task takeover` does. Found by the new serve test.
- `Sources/RielaCLI/TaskRemoteTakeover.swift`: added the `hostResolver` DI seam (production default `HostCapabilityResolver()`) so tests do not run backend probes or read the real profile.
- `Tests/RielaCLITests/TaskRemoteTakeoverTests.swift`: fixed `remotePacket` id strings that lacked the backslash (the UUID interpolation was literal text), extended the stub and node adapter, added the tests above.

## Open findings (owned by wh-20 step 3, outside this plan)

- Server schema does not register the wh-16 task-handover types. The real executor rejects the successor's `takeoverTask` (and `reportAttempt`) mutations with `invalidVariable: GraphQL variable '$input' uses unknown or non-input type 'TakeoverTaskInput'`. `graphQLInputTypeNames` (`Sources/RielaGraphQL/GraphQLVariableValidation.swift:427-441`) is built from `GraphQLContractProjector.schemaContract + GraphQLSchemaGenerator.render()`, and `taskHandoverGraphQLSchemaTypes` (`Sources/RielaGraphQL/TaskHandoverGraphQL.swift:353`) is in neither; no `takeoverTask`/`taskHandover` field or input type appears in the SurfaceCatalog or generated SDL. So remote takeover over a real `/graphql` fails at reserve time. Evidence: the two provider-backed tests fail in `focused.log`; with the variable types temporarily rewritten to `JSONObject!` in the test executor (diagnostic only, not kept) the whole suite passed 14/14 (`tmp/work-handover/wh-18-remote-takeover/test-integrity/iter2.log`). Fix is owned by `impl-plans/active/wh-20-reconcile.md` step 3 (add `taskHandoverGraphQLSchemaTypes` to `handWrittenSchemaBlocks`/`handWrittenSchemaBlockNames` and the seven root fields to the SDL), not by wh-18 or `TaskRemoteTakeover`.
