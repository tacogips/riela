# eh-07-abandoned-and-retention progress

Session: 2026-10-27, branch `feat/efficient-history`.

## Changes

- `SessionAbandonedInvocationReconciler` scans unsettled, not-yet-abandoned nested invocation rows, acquires parent/child locks in sorted order, checks terminal/age constraints, supports dry run, and marks eligible rows abandoned. It cancels a reserved `created` child with the contract reason.
- `SessionReconcileCommandRunner` accepts and validates `--abandoned-after-hours` (1...8760, default 24), then includes nested invocation verdicts in JSON and text output after the existing running-session reconciliation.
- `TerminalRetentionIndexes` uses a schema-aware settled expression so pre-generation-11 databases remain readable. `TerminalRetentionMetadata` counts root payload blobs and no longer protects an absent child when the row is explicitly abandoned.
- `TerminalRetentionExecutor` removes runtime execution rows, root payload blobs, and nested invocation references during family deletion; `SessionRetentionTombstones` prevents retired writers from recreating execution/payload rows.
- `RunEndStorageMaintenance` performs capped incremental vacuum and passive WAL checkpoint only for incremental-auto-vacuum stores. `AutomaticRetentionHook` invokes it for the same explicit/project/user stores after its existing applicability gate, independent of policy configuration.
- Tests added/extended: `SessionAbandonedInvocationTests`, `RunEndStorageMaintenanceTests`, `SessionReconcileCommandTests`, and `TerminalRetentionTests`.
