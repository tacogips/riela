# ISW2-32 recovery hydration progress

## Root cause

Resume, rerun and workflow `--resume` previously seeded the complete persisted history before emitting the first JSONL event. The path decoded every CLI record and message, loaded every remaining canonical snapshot, and the FailClosed wrapper performed another `loadAll()`. The resulting pre-event cost scaled with unrelated session count and payload size. The issue report's long low-CPU wait was not reproduced; this change addresses the confirmed O(store) hydration path only.

## Implementation

- Replaced the implicit `hydrateSessions` switch with required `.none` and `.family(of:)` modes. Metadata identity observations and stale-projection retry now run in both modes.
- Added indexed canonical session-family lookup and per-family targeted snapshot loading.
- Session resume/rerun and workflow `--resume` select the target family; fresh workflow and package parity runs select `.none`.
- FailClosed hydration reads the requested family only. Its terminal persistence predicates remain unchanged.
- Added large-history family-scope, identity high-water, `.none`, CLI-only target, FailClosed, workflow-message, and first-JSONL timing coverage.
